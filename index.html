Manual Location Override: API Specification

RESTful Architecture, Request/Response contracts, and Automated Lifecycle Triggers

1. RESTful API Endpoint Design
PATCH /api/shipments/:trackingNumber/location-override

Safely overrides the package physical location string, triggers status mutation to "Sorting at Destination Facility", writes to the immutable audit trail, and fires recipient notification payloads.

Structured JSON Request Payload:

{ "is_manual_override": true, "location_string": "Grid Section C, Berth 4", // Free-form string, max 150 chars "override_reason": "Package too large for bins", // Mandatory justification "admin_user_id": "nimissolomon@gmail.com", // Admin audit attribution "coordinates": { // Optional geo-coordinates "latitude": 51.1537, "longitude": -0.1821 }, "override_status": "Sorting at Destination Facility" }

Structured JSON Response Format (200 OK):

{ "success": true, "message": "Manual location override applied and broadcast successfully.", "audit_id": "audit-1775482910-xyz", "tracking_number": "SHIP-DEMO0001", "updated_location": "Grid Section C, Berth 4", "status": "Sorting at Destination Facility", "webhook_event": { "event_id": "wh-evt-88192", "event_type": "shipment.manual_location_override.broadcast", "created_at": "2026-10-06T15:35:00.000Z", "data": { "channels": { "sms": { "dispatched": true, "message": "Package arrived locally at Grid Section C, Berth 4" }, "email": { "dispatched": true } } } } }
